# Франкенштейн

Браузерная игра для 2–8 человек. Ведущий загадывает зверя и выбирает схему тела. Каждый получает задание без названия животного, рисует в своей области и не видит чужие рисунки. После сдачи всех фрагментов игра собирает общий холст и раскрывает слово. Результат скачивается как PNG. Есть кисть, заливка замкнутой области, линия, прямоугольник и эллипс. Фигуры можно заливать выбранным цветом. Все инструменты ограничены своим фрагментом и поддерживают отмену.

## Запуск

Нужен Node.js 22.12 или новее.

```sh
npm ci
npm run dev
```

Открой адрес, показанный Vite. ES-модули требуют HTTP: двойной щелчок по HTML-файлу не поддерживается.

```sh
npm test
npm run build
npm run preview
```

В `dist/` находится готовый статический сайт. Сервер приложения для размещения не нужен.

## Мастерская схем

Открывается с главного экрана даже без подключения к сети. В комнате редактор доступен ведущему.

1. Добавь фотографию или рисунок зверя как подложку.
2. Выдели прямоугольные области мышью или пальцем. Края примагничиваются; области не должны пересекаться. Вокруг зверя можно оставить свободное место.
3. Подпиши задания без названия зверя: «голова с ушами», «туловище с лапами». Добавь подсказки о направлении и стыках.
4. В режиме стыков подпиши соединение и отметь две его крайние точки на одной общей границе (например, края шеи). Игроки увидят совпадающие отрезки с направляющими, стрелками и подписью. Повторное нажатие убирает весь стык.
5. Сохрани схему. Она останется в этом браузере вместе с уменьшенной подложкой. Чтобы передать её другому ведущему, нажми «Поделиться схемой». Другой ведущий выбирает «Добавить из файла».

Схему можно открыть кнопкой «Изменить схему». Сохранение в файл доступно и в редакторе. Очистка данных сайта удаляет локальную библиотеку, поэтому важные схемы лучше выгрузить.

Задания адаптируются к числу участников: лишние области объединяются, недостающие получаются делением крупных. Соседние прямоугольники объединяются без внутреннего шва. Каждая исходная область назначается одному игроку. Непрямоугольный фрагмент может состоять из нескольких выделенных областей одного игрока. Система перераспределяет геометрию и готовые инструкции; она не придумывает анатомию по фотографии.

Подложка, ключевые слова схемы и название зверя до финала не передаются участникам. Задания и геометрия доступны браузерам участников; публичный брокер не обеспечивает защиту от намеренного вмешательства.

## Мультиплеер

Используется MQTT over WebSocket с публичным брокером shiftr.io на порту 443. Большие сообщения передаются ограниченными частями и собираются на принимающей стороне. Это внешняя инфраструктура, но устанавливать или обслуживать свой сервер не требуется. Ведущий отправляет полное приглашение: в него входят случайный идентификатор комнаты и адрес брокера. Нельзя передавать только короткую надпись комнаты.

Все участники используют один брокер. При сбое клиент переподключается к нему же, подписывается заново и запрашивает состояние. Сдача рисунка повторяется до подтверждения состоянием хоста. Дубликаты и сообщения от прошлых раундов игнорируются. Промежуточные штрихи остаются во вкладке рисующего; хост получает их только при сдаче. На ход отводится 75 секунд; хост пропускает не ответившего участника после небольшого запаса времени.

Ограничения:

- Вкладка ведущего должна оставаться открытой. Перезагрузка ведущего завершает текущую комнату; автоматического переноса хоста нет.
- Перезагрузка игрока создаёт нового участника. Восстанавливаются обрывы соединения внутри открытой вкладки, а не перезагрузки страницы.
- Браузеры могут замедлять фоновые вкладки, особенно на телефонах. Лучше держать игру на экране.
- Публичные брокеры могут быть недоступны или блокироваться провайдером. Ведущий может выбрать другой WSS-брокер при создании комнаты; приглашать игроков нужно заново.
- Сообщения проходят через публичную инфраструктуру. Не используйте игру для личных данных. В приглашении нет аутентификации или сквозного шифрования.

Для воспроизводимой локальной проверки без доступа к публичным брокерам:

```sh
npm run test:broker
```

Открой игру на `localhost`, укажи `ws://localhost:18889` в поле брокера и проверь в двух вкладках. Незащищённый WS разрешён только для локального тестового адреса; на опубликованном сайте используется WSS. Тестовый брокер не входит в сборку сайта.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает сайт после push в `main`, запускает тесты и публикует `dist/`. В настройках репозитория нужно выбрать **Settings → Pages → Source → GitHub Actions**. Сборка использует относительные пути и поддерживает размещение в подпапке репозитория.

## Модули

- `src/game.js` — правила, задания, очередь, таймер, сдача и финальное состояние.
- `src/fill.js` — заливка с ограничением области.
- `src/protocol.js` — разбиение и сборка сетевых сообщений.
- `src/network.js` — MQTT, подписки, переподключение и приглашения.
- `src/schemas.js` — формат схем, валидация, распределение областей, локальная библиотека и экспорт.
- `src/editor.js` — визуальная разметка подложки.
- `src/drawing.js` — ввод штрихов, ограничение области и сборка общего рисунка.
- `src/main.js` — интерфейс и координация модулей.

Тесты проверяют переходы раундов, тайм-ауты, повторные сдачи, позднее подключение, валидацию рисунков и схем, отсутствие секрета в состоянии до финала и распределение областей для 2–8 игроков.
