# Франкенштейн

Игра для 2–8 человек: общее расположение частей, но разные секретные замыслы. Один рисует голову недовольного инспектора, другой — туловище свадебного торта, третий — конечности космического сантехника. Общий рисунок открывается в финале вместе с заданиями художников.

Комнаты, присутствие, приватные задания и чат работают через Firebase Realtime Database. Брокеры и собственный сервер не нужны. Сайт размещается на GitHub Pages.

## Запуск

Нужен Node.js **24.12 или новее**. В проекте есть `.nvmrc`.

```sh
nvm use
npm ci
npm run dev
```

`firebase-config.json` содержит публичные настройки веб-приложения. Безопасность обеспечивается правилами базы и Firebase Authentication, а не сокрытием API key. Service account и приватные ключи в браузер не передаются. Analytics и Cloud Storage не используются.

```sh
npm test
npm run build
npm run preview
```

`dist/` — готовый статический сайт. Исходный HTML без сборки публиковать нельзя.

## Firebase

В проекте `frankenstain-7d82f` используются:

- Authentication → Anonymous: вход без регистрации и пароля.
- Realtime Database: комнаты, слоты участников, присутствие, сообщения и состояние раунда.
- Правила `firebase/database.rules.json`: закрытое состояние ведущего, персональные ответы, проверка автора сообщений и профилей, максимум восемь слотов.

Для нового проекта нужно заменить `firebase-config.json`, включить Anonymous, создать Realtime Database и опубликовать правила:

```sh
npx firebase login --reauth
npx firebase deploy --only database --project frankenstain-7d82f
```

GitHub Actions собирает и публикует сайт, но не получает административные ключи Firebase и не изменяет правила базы автоматически.

Ориентир для бесплатного Spark на 20 ноября 2026 года: 100 одновременных подключений на проект, 1 ГБ данных, 10 ГБ исходящего трафика в месяц. Одна вкладка — отдельное подключение. Проверять актуальные лимиты: [Firebase Pricing](https://firebase.google.com/pricing), [Realtime Database FAQ](https://firebase.google.com/docs/database/faq-and-troubleshooting).

## Комнаты и чат

Выбери имя и одного из 24 аватаров-человечков, создай комнату и отправь друзьям шестизначный код или ссылку. В комнате видно, кто онлайн; ведущий может убрать участника. В чате сохраняются последние 100 сообщений, новые сообщения отмечаются счётчиком. Текст сообщений отображается как текст, а не HTML.

Обновление страницы возвращает в ту же комнату с тем же персонажем. Восстанавливаются состояние ведущего, задания, сданные рисунки и локальный несданный набросок. Дублированная вкладка получает отдельную личность вместо второго управляющего одной комнатой. Онлайн-присутствие учитывается по отдельным соединениям: закрытие старой вкладки не выключает новую.

Ведущий управляет ходами в своём браузере. Если его соединение прервалось, состояние хранится в Firebase; для продолжения он должен вернуться. Автоматического переноса роли ведущего пока нет. Закрытие комнаты ведущим удаляет её данные. Код действует до суток; проверка срока не заменяет автоматическую серверную уборку оставленных комнат.

## Основной режим: «Кажется, мы рисовали разное»

Ведущий выбирает геометрию из 60 персонажей или своей схемы, секретное слово и время на фрагмент: **10–180 секунд с шагом 10**, по умолчанию 60. Есть случайный выбор персонажа без повторов до конца колоды и автоматический выбор нового персонажа для следующего раунда.

У каждого художника отдельный секретный образ из 12 несовместимых миров: инспектор, свадебный торт, надувная уточка, офисный принтер, бабушкин любимчик, надувной качок, король дискотеки, космический сантехник, живой суп, сомнительный люкс, пират и неловкий гость. В одном раунде образы участников не повторяются.

Подсказки написаны отдельно для головы, туловища, конечностей, хвоста, крыльев, шеи, раковины, щупалец, шляпки и плавников. Игрок с крылом не получает инструкцию рисовать ноги. Авторские пояснения пользовательских схем сохраняются отдельно.

Слева разделены собственный участок, секретное задание и статус текущего хода. Общая готовность — не номер чужого этапа. В плане свой фрагмент жёлтый, остальные нейтральные. На холсте видны парные стыки, но чужих рисунков и секретных заданий в персональном ответе нет.

Задания адаптируются к 2–8 игрокам. Соседние совместимые области объединяются; при делении крупной области стыки пересчитываются на реальной общей границе. Головы не делятся, пока есть другие подходящие области. На финальном экране раскрываются авторы и их несовместимые задания. Результат скачивается как PNG.

## Мастерская схем

Работает до входа в комнату. Можно загрузить подложку, разметить прямоугольные области, подписать задания и отметить двумя точками каждый стык. Края областей примагничиваются. Подложка, название схемы и исходный контур остаются у ведущего.

Генератор из обводки:

1. Загрузи картинку и нажми «Обвести силуэт».
2. Обведи внешний контур одним движением.
3. Выбери 2–8 частей и направление разрезов.
4. Нажми «Разбить на части»: появятся области и парные стыки.
5. Проверь названия частей и уточни авторские подсказки.

Генератор делает геометрическое разбиение, а не распознаёт анатомию по картинке. Сложные случаи лучше разметить вручную.

Схемы вместе с уменьшенной подложкой и контуром хранятся в браузере. Их можно выгрузить файлом и передать другому ведущему. Редактирование встроенной схемы создаёт свою копию под текущее число участников.

Инструменты рисования: кисть, заливка замкнутой области, линия, прямоугольник и эллипс. Фигуры можно заливать; действия отменяются. Все инструменты ограничены назначенными областями.

## Локальные эмуляторы и проверки правил

Дополнительно нужен Java 21+. Команды запускаются в двух терминалах:

```sh
npm run emulators
npm run dev:emulator
```

Режим `emulator` использует отдельный demo-проект и не пишет в настоящую базу. Интерфейс Firebase Emulator Suite доступен на `http://127.0.0.1:4000`.

Когда эмулятор запущен:

```sh
npm run test:firebase
```

Или автоматически запустить только базу, проверить правила и остановить эмулятор:

```sh
npm run test:emulator
```

Правила тестируются в отдельном namespace, чтобы не очищать комнату открытого браузерного теста. Проверяются приватность чужих ответов, запрет изменения состояния ведущего и чужих профилей, авторство чата, лимит участников и освобождение слота.

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускает модульные тесты, проверки правил Firebase на эмуляторе и сборку. После загрузки артефакта отдельное зависимое задание публикует `dist/`.

В репозитории: Settings → Pages → Source → GitHub Actions; окружению `github-pages` нужно разрешить публикацию из `main`. Относительные пути поддерживают размещение в подпапке.

## Модули

- `game.js` — правила, очередь ходов, время, приватные снимки и восстановление.
- `firebase-client.js`, `firebase-room.js` — анонимный вход, комнаты, транзакции слотов, присутствие и чат.
- `room-ui.js`, `avatars.js`, `room-code.js`, `tab-identity.js` — персонажи, чат, короткие приглашения и личность вкладки.
- `hybrid.js`, `task-roles.js`, `task-geometry.js`, `player-status.js` — независимые секретные образы, семантика частей, геометрия стыков и понятный статус художника.
- `schema-presets.js`, `schemas.js`, `overview.js` — геометрические схемы, распределение частей и план без чужих секретов.
- `editor.js`, `contour.js` — редактор и генератор схем из обводки.
- `drawing.js`, `fill.js` — инструменты и сборка общего рисунка.
- `main.js` — интерфейс и координация модулей.

## План следующих режимов — пока не реализованы

Сначала стабилизируем основной слепой гибрид. Остальные варианты сохранены для отдельных решений:

1. **Подстава от друга:** перед раундом сосед назначает совместимое с твоей частью нелепое условие; в финале раскрывается автор подставы.
2. **Разные вселенные:** части рисуются в несовместимых жанрах — хоррор, реклама недвижимости, детская книга, инструкция к пылесосу.
3. **Испорченный художник:** незаконченная часть передаётся соседу с новым заданием; исходная задача скрыта, в финале видна история превращения.
4. **Срочно исправьте:** несколько коротких раундов над одним существом — собеседование, провал собеседования, собственный бизнес.
5. **Кто это вообще:** имя и профессия существа от игроков, затем голосование и раскрытие исходного слова.
6. **Художественное ограничение:** один штрих, только фигуры, огромная кисть или три цвета. Включается добровольно.
7. **Защита диплома:** художники объясняют, зачем существу их деталь; голосуют за самое убедительное враньё.

Дальнейшая инфраструктура: перенос ведущего при уходе, автоматическая уборка брошенных комнат, общая библиотека схем и галерея результатов. Это отдельные задачи, не обещания текущей версии.
